# Simulation Lab UI

Status **Implemented for local simulation**. See the [requirements](../requirements/simulation-lab.md) and [storefront flow](https://drive.google.com/file/d/1O30WveamPeeYuu_UR3s8QbQQNJ_usX_u/view).

1. Choose **Travel** or **Online store** in the purple storefront. Product cards use custom photos to distinguish products. Choose a date or delivery option and quantity in **Checkout details**.
2. For the first order, optionally enter a synthetic name, email, and phone in **Contact**. Use an address under `.test`, such as `buyer@traveler.test`. For flight tickets, turn on **Block flights for restricted.test** to exercise the demo policy.
3. Open **Simulation settings** to choose normal, fraud or mixed traffic and change the seed, accounts, orders/minute, and edge cases.
4. Choose **Run batch simulation** in the inline summary. When an eligible shared checkout's first payment-stage event has final action `ALLOW`, **Pay in test mode** opens the Omise-hosted card form. The same panel shows the outcome, including pending or unknown, for the one attempt saved with the run. [Sandbox setup and test steps](../simulation-runbook.md#omise-sandbox-checkout)
5. In **Batch simulation results**, choose a row in **Event decisions** to open its **Decision evidence**. The display status summarizes the saved engine action, which appears in the evidence alongside the platform action, batch policy, action source, mock Jev result, rule hits, missing signals, and 60-second order counts. With contact details entered, the lab selects the first order's payment-stage event. Both stages show the submitted contact from browser memory and the event email domain used for assessment.
6. Score the saved run from the **Offline QA** panel. The report shows metrics and the confusion matrix. An undefined rate displays an em dash, and timeouts are included in the unscored count.

**Shared signals in this run** shows other synthetic accounts that used the same device, IP or payment token earlier in that run. Each matching account links to its latest earlier event for that signal. The list shows the first five accounts per signal with an option to expand the remaining entries. A shared IP can appear on an Approved event when accounts use the same Wi-Fi. The 60-second order counts come from the decision engine's recorded features.

Open the results through **Testing → Simulation Lab**. After a shared batch finishes, select **Open saved run** to open a read-only view using the run UUID. Existing `/simulation-lab#fraud-network` links open the same results section. Row and source-event controls move focus to **Decision evidence**. **Back to selected event** returns focus to the row. The page keeps the storefront and setup beside the inline summary on desktop and stacks them on mobile. [Saved run walkthrough](../simulation-runbook.md#verify-batch-decision-evidence)
