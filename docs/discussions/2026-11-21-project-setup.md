# Project setup and knowledge vault

The project owner requested separate frontend and backend folders, a coordinated delivery workflow, and a Markdown second brain compatible with Obsidian.

- Delivery follows planning, design, development, testing, and deployment. Failed tests feed back into development.
- Substantive discussions, requirements, and UI designs belong in the project vault. The [knowledge index](../home.md) links to each area.
- Frontend and backend start empty. Product requirements, the technology stack, and a deployment target are open.

See the [project brief](../project.md) for current project context and the [delivery workflow](../workflow.md) for agent responsibilities.
